2. Rolling Spend Logic (30/90)

Purpose:
Measure short-term pressure versus medium-term baseline.

Definitions:
	•	spend30 = total allocated lobbying spend in the last 30 days
	•	spend90 = total allocated lobbying spend in the last 90 days

Concept:
	•	30-day spend captures current pressure
	•	90-day spend captures baseline trend
	•	Comparing the two gives you acceleration or slowdown

Core pattern:
SUM(CASE WHEN as_of_date >= CURRENT_DATE - 30 THEN allocated_amount ELSE 0 END) AS spend30,
SUM(CASE WHEN as_of_date >= CURRENT_DATE - 90 THEN allocated_amount ELSE 0 END) AS spend90

Best practice:
Aggregate by canonical_issue, not by raw issue fields.

Example view structure:
DROP VIEW IF EXISTS public.v_lobbying_spend_rolling CASCADE;

CREATE VIEW public.v_lobbying_spend_rolling AS

    SELECT
        COALESCE(im.canonical_issue, 'Other') AS canonical_issue,
        a.as_of_date,
        a.allocated_amount
    FROM public.v_lobbying_activity_allocated a
    LEFT JOIN public.issue_keyword_map im
      ON (im.code = a.general_issue)
         OR (
              im.keyword IS NOT NULL
              AND LOWER(a.description) LIKE '%' || LOWER(im.keyword) || '%'

SELECT
    canonical_issue,

    SUM(CASE WHEN as_of_date >= CURRENT_DATE - 90 THEN allocated_amount ELSE 0 END) AS spend90
FROM alloc
WHERE canonical_issue IS NOT NULL
GROUP BY canonical_issue;

3. Momentum Formula

Purpose:
Translate rolling spend into an interpretable signal of policy pressure.

Base version
momentum = spend30 / spend90

Interpretation
	•	> 1.0 = accelerating pressure
	•	**~ 1.0** = stable pressure
	•	< 1.0 = weakening pressure

Safer version

To avoid divide-by-zero:

CASE
  WHEN spend90 = 0 THEN NULL
  ELSE spend30::numeric / spend90
END AS momentum

More stable version

To prevent very small denominators from creating fake spikes:

spend30::numeric / NULLIF(spend90, 0)

Optional enhanced version

You were moving toward a combined score:

signal_score = momentum * log(1 + spend30)

That gives you:
	•	direction from momentum
	•	magnitude from spend size

4. Tuning Dimensions (Very Important)

These are the core levers you wanted preserved for calibration.

A. Committee Dominance

Controls whether heavily connected committees overpower the signal.

Use for:
	•	preventing one institutional channel from dominating
	•	balancing broad lobbying activity vs concentrated committee influence

⸻

B. Role-Weight Curve Severity

Controls how sharply influence increases with role importance.

Use for:
	•	deciding whether senior actors get slightly more weight or dramatically more weight
	•	adjusting the curve from linear to nonlinear

Examples:
	•	flat weighting
	•	linear weighting
	•	exponential/power curve weighting

⸻

C. Overlap Inflation

Controls double-counting when one filing matches multiple issues or multiple keywords.

Use for:
	•	avoiding artificial inflation of issue pressure
	•	making multi-match records fair instead of duplicated

⸻

D. Recency Weighting

Controls decay over time so recent activity matters more than older activity.

Use for:
	•	sharpening the responsiveness of the model
	•	balancing noise vs speed

Conceptual formula:
recency_weight = e^(-λ * days_old)

Higher lambda = faster decay
Lower lambda = slower decay

⸻

E. Niche Issue Weighting

Prevents low-volume but strategically important issues from disappearing.

Use for:
	•	preserving visibility for smaller topics
	•	allowing under-covered issues to surface if activity is concentrated or unusual

⸻

5. Allocation Method

Purpose:
Handle records that map to more than one issue without overstating total spend.

Core rule

If one record maps to multiple issues, divide the amount across them.

Formula

allocated_amount = total_amount / number_of_matched_issues

Example

If a $90,000 filing matches 3 canonical issues:

allocated_amount = 90,000 / 3 = 30,000 per issue

Why this matters

Without allocation:
	•	one filing counted across 3 issues becomes $270,000 of fake signal

With allocation:
	•	total spend remains preserved
	•	issue-level pressure stays realistic

Optional future extension

Weighted allocation instead of equal split:

allocated_amount = total_amount * issue_weight / sum_of_issue_weights
That would let you favor stronger matches later.

🔐 ENVIRONMENT CONFIGURATION (.env)

📁 What the .env file is

A .env file is a local configuration file that stores:
	•	API keys
	•	database connections
	•	runtime settings

👉 It allows your code to:
	•	stay secure (no hardcoded secrets)
	•	be portable across machines
	•	be reproducible in new sessions

⸻

📍 Location

In this project:
pause-altdata-ingest/
    policy_ai_agent/
        .env   ← (this file)

👉 Must live inside policy_ai_agent/ to be picked up by scripts
